# Agent-facing RPC performance contract proposal

Observed public-path baseline:12 requests/mode, sequential, four read methods; median~1.25s and p95~1.6s, no clear keep-alive improvement. Small non-randomized probe, not a causal backend diagnosis. Existing canonical endpoints remain authoritative. This proposal has NOT been implemented on the VM/server.

Current Agent1 changes: pooled HTTP connections; independent game/input/rules/balance reads in parallel; per-cycle same-game settlement report and input coalescing; bounded feedback work during the explicit30min/100-throw test; method-only latency/error/bytes telemetry. No stale auth/nonce/balance caching and no signed replay. Ordinary30s cadence defaults remain unchanged.

Proposed native calls (read-only):

1. colliderV2.getAgentFrame({user,game_id,map_ids,known_catalog_revision,game_cursor,limit}). One accepted-state read lock/snapshot returns chain/domain/accepted-block identity,height,time; wallet balances and protocol nonce reservation state; bounded open-game summaries with own throw/value counts and protocol admissibility; chosen game's untouched canonical simulation input and snapshot hash; exact live oracle prices, age, status and expiry; separate allowed-asset metadata/catalog revision and artifact bindings. Agent-specific reserve, risk and doctrine filters stay local. Cap game count and reply bytes, with pagination. Return exact monetary integers as strings. Differentiate stable catalog data from mutable wallet/board data. Never merge hypothetical planning metadata into the frozen canonical confirmation input.

2. colliderV2.getAgentChanges({user,since_height,tracked_game_ids,cursor,limit}). Ordered accepted-chain changes with generation/sequence, explicit gap or fork detection, bounded changed games, wallet events and settlement references. Missing/gapped cursor requires a fresh frame; it must never be silently interpreted as an unchanged nonce or a zero balance. A WebSocket/SSE transport can carry the same immutable sequence contract to agents and frontend.

3. colliderV2.getAgentResults({user,after_settled_height,game_ids,cursor,limit}). Batched canonical settled throw IDs, exact inputs/returns by asset, points awards and game-level attribution with accepted/settled heights. Fetch one game report once, rather than once per pending throw. Include full immutable history references needed by reveal/HPS verification, with bounded pages rather than silent truncation.

Keep prepareSignedIntent/submitSignedIntent as the single canonical write flow. If preparing against a frame is added, require expected frame hash/height and return explicit stale-frame errors plus the same locally verified native envelope. No optimistic client-generated nonce/signature, automatic write retry or unverified fast acceptance path.

Measurement: p50/p95/p99 network latency, payload bytes, RPCs per accepted throw, preparation-to-canonical-acceptance time, server accepted-height lag, retries/429/503, fairness distributions across all four wallets, cache hit provenance, planning/feedback CPU time, and settlement/publication lag separately. Shared quotas and documented queue ordering must prevent cheap polling from winning priority. Measure cold/warm, concurrent four-agent and frontend-contended conditions with identical budgets. Set deployment-specific latency SLOs only after isolating WAN/TLS/gateway/VM and disk costs; this run is a diagnostic, not an AAA certification.

Transport probe during this run: cold TCP~320ms,TLS complete~958ms,total~1278ms; reused TCP/TLS total~359ms. Native HTTP/2 ALPN negotiation was rejected (no application protocol), so the h2 read prototype sent no RPC requests and was not installed in the live signers. Warm live RPC medians were~321ms,p95~1s at8min with zero errors. This is a WAN/transport observation, not evidence of a specific VM CPU bottleneck.

Four-hour continuation evidence (13 November Perth): 3,200 new accepted throws across four wallets, 108,353 observed trader RPCs, one recovered HTTP502 on a fresh oracle read; p50 about319ms and p95 about983ms. Approximately33.86 RPCs per accepted throw remain. These observations exclude controller/audit traffic and are not a server-only latency or global fairness certificate. At the final audit, 137 of 238 played games were absent from the live native list; both getGame and getGameReport returned game-not-found for a sampled older game. Retained Classic-filtered observations provided map provenance, while the last game remained Open with eight accepted throws. The proposed agent result/history contract therefore needs explicit archive references, retention/gap semantics and accepted-height provenance; missing records must never be silently treated as zero activity or a different map. Server endpoints remain a proposal, not deployed.
